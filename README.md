# توثيق الأعطال — Ops11141/mn

واجهة عربية لمشروع توثيق الأعطال لقسم الصيانة بالشركة السعودية للطاقة.

## الملفات
- `index.html`: واجهة عامة للبحث واستعراض الأعطال والصور، وتسجيل دخول المشرف، وإضافة الأعطال وتحديث حالتها.
- `supabase-config.js`: إعدادات المتصفح العامة؛ أدخل فيه Project URL والمفتاح العام anon/publishable فقط.
- `supabase/schema.sql`: مخطط قاعدة البيانات وسياسات الوصول والتخزين.
- `supabase/status-migration.sql`: ترحيل قاعدة البيانات الحالية إلى حالتي العمل المعتمدتين.

## طريقة العمل المعتمدة
- الحالات فقط: `تم الانتهاء` و`تم الانتهاء وبحاجة إلى جدولة`.
- يمكن للزائر قراءة السجلات والصور والبحث دون تسجيل دخول.
- المشرف المعتمد فقط يمكنه الإضافة وتغيير الحالة وإضافة صور بعد الإصلاح وحذف السجلات.
- صور قبل الإصلاح ترفع مع إنشاء السجل، ويمكن إضافة صور بعد الإصلاح لاحقًا من بطاقة السجل؛ الصور تحفظ في Storage وروابطها في قاعدة البيانات.
- الصور يعاد تحجيمها وضغطها داخل المتصفح قبل رفعها لتقليل حجم التخزين.

## ما تم ربطه برمجيًا
الواجهة أصبحت تستخدم Supabase Auth وDatabase وStorage. يلزم إدخال بيانات الاتصال العامة الصحيحة في `supabase-config.js` قبل أن تتصل فعليًا بمشروع Supabase. كما يلزم تشغيل ملف `supabase/status-migration.sql` في SQL Editor لأن قاعدة البيانات كانت قد أُنشئت قبل اعتماد الاسمين النهائيين للحالتين.

## خطوات الإكمال
1. من Supabase افتح Project Settings ثم API (أو API Keys) وانسخ Project URL والمفتاح العام anon/publishable.
2. ضع القيمتين في `supabase-config.js`. لا تضع مفتاح `service_role` أو أي Secret key في الموقع.
3. شغّل محتوى `supabase/status-migration.sql` مرة واحدة في SQL Editor.
4. تأكد أن حساب المشرف موجود في `public.admin_profiles` وأنه يستخدم البريد وكلمة المرور الخاصين بحساب Supabase Auth.
5. اختبر القراءة العامة، وتسجيل دخول المشرف، وإضافة عطل مع صور، وإضافة صور بعد الإصلاح، وتغيير الحالة من جهاز آخر.

## الأمان
تُنفّذ صلاحيات الكتابة في سياسات RLS داخل Supabase، وليس اعتمادًا على إخفاء الأزرار في الواجهة فقط. لا تستخدم مفتاح service_role في الواجهة أو المستودع العام.

قبل الاستخدام التشغيلي الفعلي، اختبر تسجيل الدخول ورفع الصور والصلاحيات من حساب مشرف ومن جلسة عامة.
