# توثيق الأعطال — Ops11141/mn

واجهة عربية لمشروع توثيق الأعطال لقسم الصيانة بالشركة السعودية للطاقة، بتصميم داكن متدرج مستوحى من أداة فحص المواقع.

## الملفات
- `index.html`: الواجهة العامة، البحث والتصفية، مؤشرات الحالة، ونموذج تجريبي لإضافة سجل.
- `supabase/schema.sql`: مخطط قاعدة البيانات وسياسات أمان Supabase المقترحة.

## الصلاحيات المطلوبة
- العامة: استعراض سجلات الأعطال والصور والبحث دون تسجيل دخول.
- المشرفون المعتمدون فقط: إضافة السجلات وتعديلها وحذفها ورفع الصور، بعد تسجيل دخول حقيقي.

## حالة الربط الحالية
واجهة الموقع لا تزال نسخة أولية وتخزن السجلات محليًا في المتصفح. ملف `supabase/schema.sql` أُضيف كخطوة تجهيز للقاعدة والسياسات، لكنه لم يُشغّل داخل مشروع Supabase ولم تُربط الواجهة به بعد. لذلك لا توجد مصادقة حقيقية أو قاعدة مشتركة فعالة حتى الآن.

## خطوات ما قبل التشغيل الفعلي
1. إنشاء مشروع Supabase وتطبيق `supabase/schema.sql` في SQL Editor.
2. إنشاء حساب المشرف الأول في Supabase Auth ثم إدراج معرّف المستخدم في `public.admin_profiles` يدويًا حسب التعليمات الموجودة في نهاية ملف SQL.
3. إضافة عنوان مشروع Supabase ومفتاح `anon` العام إلى إعدادات الواجهة، ثم ربط تسجيل الدخول والاستعلامات ورفع الصور بالخدمة.
4. عدم وضع مفتاح `service_role` في الواجهة أو المستودع العام.
5. اختبار أن العامة يستطيعون القراءة فقط، وأن المستخدم غير المدرج في `admin_profiles` لا يستطيع الكتابة حتى عند استدعاء API مباشرة.

## معاينة
يمكن فتح `index.html` لمعاينة التصميم فقط. لا تستخدم النسخة الحالية لتوثيق بيانات تشغيلية حقيقية قبل إكمال الربط والاختبارات.
